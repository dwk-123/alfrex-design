# Alfrex shadcn setup

Follow this literally. Commands assume a Next.js App Router project with
`@/*` mapped to `src/*` and the skill installed at
`.agents/skills/alfrex-shadcn/`. If the skill is installed elsewhere (for
example, `.claude/skills/alfrex-shadcn/`), substitute its resolved directory in
every `cp` command.

## 1. Verify or initialize shadcn

The supported configuration is shadcn v4, Tailwind v4, **Base UI** (not Radix),
style `base-nova`, neutral base, CSS variables, and Lucide icons.

If `components.json` exists, verify these fields before copying anything:

```json
{
  "style": "base-nova",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/app/globals.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "iconLibrary": "lucide"
}
```

Also verify `package.json` uses Tailwind 4 and contains `@base-ui/react`. A
Radix-based shadcn app must be migrated to Base UI before installing the Alfrex
component sources.

For a fresh Next app with no `components.json`, run:

```bash
npx shadcn@latest init --defaults
```

`--defaults` currently means the Next template with the `base-nova` preset.
Inspect the generated `components.json`; do not continue unless it matches the
fields above. Do not select `nova`/Radix or a non-neutral base.

## 2. Install stock components

Install the stock base-nova pieces used by the recipes and page archetypes:

```bash
npx shadcn@latest add card dialog input label textarea table tabs select dropdown-menu sonner checkbox sheet separator
```

Use stock shadcn for card, dialog, form controls, table, tabs, menus, toast,
checkbox, sheet, and separator. Alfrex changes their semantic theme; it does not
fork those source files.

## 3. Copy the theme

```bash
cp .agents/skills/alfrex-shadcn/assets/alfrex-theme.css src/app/alfrex-theme.css
```

The copied file starts with an upstream provenance warning. Do not edit its
tokens in the consumer. Update the installed skill and recopy instead.

Tailwind requires imports to remain top-level. Replace the import/custom/base
portion of `src/app/globals.css` with this stack:

```css
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";
@import "./alfrex-theme.css";

@custom-variant dark (&:where(.dark, .dark *));

@layer base {
  * {
    @apply border-border outline-ring/50;
  }
  body {
    @apply bg-background text-foreground;
  }
  html {
    @apply font-sans;
  }
}
```

Remove the stock `:root`, `.dark`, and `@theme inline` blocks generated by
shadcn. They are replaced by `alfrex-theme.css`. Do not retain a second semantic
token block: duplicate `--primary`, `--background`, or font aliases create mode
drift.

## 4. Configure IBM Plex with next/font

In `src/app/layout.tsx`:

```tsx
import { IBM_Plex_Mono, IBM_Plex_Sans } from "next/font/google"

const plexSans = IBM_Plex_Sans({
  variable: "--font-plex-sans",
  subsets: ["latin"],
  weight: ["400", "500", "600", "700"],
})

const plexMono = IBM_Plex_Mono({
  variable: "--font-plex-mono",
  subsets: ["latin"],
  weight: ["400", "500", "600"],
})
```

Apply both variables to the `<html>` element. The base layer applies
`font-sans` to that same element, so the next/font variables must be in scope
there rather than only on a descendant body:

```tsx
<html
  lang="en"
  className={`${plexSans.variable} ${plexMono.variable} antialiased`}
>
  <body>{children}</body>
</html>
```

Use those variable names exactly. The theme intentionally declares
`--font-sans` and `--font-mono` only inside `@theme inline`; next/font declares
`--font-plex-sans` and `--font-plex-mono`. Reusing `--font-sans` in next/font
creates a CSS variable cycle and silently falls back to the system font.

## 5. Copy Alfrex component sources

Review local modifications before replacing an existing button. Then copy:

```bash
cp .agents/skills/alfrex-shadcn/assets/components/{button,status-pill,metric,filter-chip,nav-item,field,empty-state,inline-alert}.tsx src/components/ui/
```

These files expect the normal shadcn alias `@/lib/utils` and dependencies
installed by shadcn: `@base-ui/react`, `class-variance-authority`, and
`lucide-react`.

The replacement `button.tsx` keeps the standard API and adds `variant="xlink"`
and `size="mini"`. `variant="destructive"` is intentionally a solid brand-red
commit action, not stock shadcn's pale destructive treatment. Use it once, only
for a money-committing action.

## 6. Dark mode

The theme activates when an ancestor has class `dark`. For a manual or system
toggle, install next-themes:

```bash
npm install next-themes
```

Create a client provider:

```tsx
"use client"

import * as React from "react"
import { ThemeProvider as NextThemesProvider } from "next-themes"

export function ThemeProvider({
  children,
  ...props
}: React.ComponentProps<typeof NextThemesProvider>) {
  return <NextThemesProvider {...props}>{children}</NextThemesProvider>
}
```

Wrap the app in layout:

```tsx
<html
  lang="en"
  suppressHydrationWarning
  className={`${plexSans.variable} ${plexMono.variable} antialiased`}
>
  <body>
    <ThemeProvider attribute="class" defaultTheme="system" enableSystem disableTransitionOnChange>
      {children}
    </ThemeProvider>
  </body>
</html>
```

Do not enable dark mode in a hybrid legacy `.als-*` app until every visible
screen has migrated; see `als-migration.md`.

## 7. Smoke check

Run:

```bash
npm run build
```

Then render both modes, keyboard-traverse each representative screen and
portal, run the app's accessibility scan, and verify:

- normal primary is neutral ink; it becomes paper-white with dark text in dark
  mode;
- destructive is red and appears only at financial commitment;
- all numbers use `font-mono tabular-nums` and numeric table cells are right
  aligned;
- cards use borders and no shadow;
- all six status pills remain readable;
- active navigation uses red wash/text/edge, while menu, select, and command
  highlights remain neutral;
- every interactive element has a clearly visible focus indicator in both
  modes and the accessibility scan has no serious or critical findings;
- browser console has no hydration, unknown-prop, or CSS import warnings.
